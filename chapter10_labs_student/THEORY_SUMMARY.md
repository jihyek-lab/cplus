## 2. 왜 템플릿이 필요한가

예를 들어 두 값을 바꾸는 함수가 있다고 합시다.

```cpp
void myswap(int& a, int& b) { ... }
void myswap(double& a, double& b) { ... }
```

이 두 함수는 로직이 거의 같고 타입만 다릅니다.  
이런 코드를 타입마다 계속 만들면 다음 문제가 생깁니다.

- 코드가 길어진다
- 같은 버그를 여러 함수에서 고쳐야 한다
- 타입이 늘어날수록 같은 패턴의 코드가 계속 복제된다

이럴 때 사용하는 것이 템플릿입니다.

## 3. 함수 템플릿

함수 템플릿은 "함수의 틀"을 만드는 기능입니다.

```cpp
template <class T>
void myswap(T& a, T& b) {
    T tmp = a;
    a = b;
    b = tmp;
}
```

여기서 `T`는 실제 타입 이름이 아니라 타입을 대신하는 매개변수입니다.

호출 예:

```cpp
int a = 3, b = 5;
double c = 1.2, d = 3.4;

myswap(a, b);   // T = int
myswap(c, d);   // T = double
```

컴파일러는 함수가 호출될 때 인수의 타입을 보고 `T`를 결정합니다.  
이렇게 실제 타입 버전이 만들어지는 과정을 구체화 또는 인스턴스화라고 합니다.

## 4. `class T`와 `typename T`

다음 두 표기는 초급 단계에서는 거의 같은 뜻으로 봐도 됩니다.

```cpp
template <class T>
template <typename T>
```

둘 다 "T는 타입이다"라는 의미입니다.  
실습에서는 둘 중 하나를 일관되게 쓰면 충분합니다.

## 5. 템플릿은 아무 타입에나 자동으로 되는 것이 아니다

초보자는 템플릿을 "모든 타입에 무조건 되는 기능"으로 오해하기 쉽습니다.  
하지만 실제로는 템플릿 내부에서 사용하는 연산이 그 타입에서 가능해야 합니다.

예:

```cpp
template <class T>
T bigger(T a, T b) {
    return (a > b) ? a : b;
}
```

이 함수가 동작하려면 `T` 타입에서 `>` 비교가 가능해야 합니다.

즉, 템플릿은 "모든 타입"이 아니라  
"이 코드가 요구하는 연산을 지원하는 타입"에 대해서만 동작합니다.

이것을 템플릿의 암묵적 제약이라고 생각하면 이해하기 쉽습니다.

## 6. 타입 추론과 타입 불일치

다음 호출은 잘 됩니다.

```cpp
int a = 3, b = 5;
myswap(a, b);
```

하지만 다음은 문제가 됩니다.

```cpp
int a = 3;
double b = 4.5;
myswap(a, b);
```

이유는 `myswap(T&, T&)`가 두 인수 모두 같은 `T`여야 하기 때문입니다.

- 첫 번째 인수만 보면 `T = int`
- 두 번째 인수만 보면 `T = double`

처럼 보이므로 컴파일러가 하나의 `T`를 깔끔하게 정할 수 없습니다.

따라서 초급 단계에서는 다음 원칙을 기억하면 좋습니다.

- 하나의 템플릿 타입 매개변수 `T`는 보통 같은 타입끼리 맞춰서 쓴다
- 서로 다른 타입을 다루려면 템플릿 매개변수를 여러 개 둘 수 있다

## 7. 템플릿 타입이 여러 개인 경우

템플릿 매개변수는 하나만 있는 것이 아닙니다.

```cpp
template <class T1, class T2>
void mcopy(T1 src[], T2 dest[], int n) {
    for(int i = 0; i < n; i++)
        dest[i] = (T2)src[i];
}
```

여기서는:

- `T1`: 원본 배열 타입
- `T2`: 목적지 배열 타입

입니다.

이런 형태는 서로 다른 타입 사이의 복사나 변환에 유용합니다.  
다만 캐스팅이 들어가면 다음 문제가 생길 수 있습니다.

- 소수점 잘림
- 정밀도 손실
- 범위 초과

그래서 단순히 "컴파일된다"와 "의미상 안전하다"는 다를 수 있습니다.

## 8. 사용자 정의 클래스와 템플릿

템플릿은 기본 자료형뿐 아니라 클래스 타입에도 사용할 수 있습니다.

예를 들어 `myswap<T>` 내부에서는:

- `T tmp = a;`
- `a = b;`
- `b = tmp;`

같은 동작을 합니다.

따라서 클래스 타입에 이 템플릿을 쓰려면, 그 클래스가 복사와 대입이 가능해야 합니다.

핵심은 이것입니다.

- 템플릿은 "기본 타입 전용 기능"이 아니다
- 중요한 것은 타입 이름이 아니라, 그 타입이 어떤 연산을 지원하느냐이다

## 9. 클래스 템플릿

함수뿐 아니라 클래스도 템플릿으로 만들 수 있습니다.

```cpp
template <class T>
class MyStack {
    T data[100];
};
```

사용할 때는 타입을 직접 적습니다.

```cpp
MyStack<int> s1;
MyStack<double> s2;
MyStack<char> s3;
```

여기서 중요한 차이는:

- 함수 템플릿은 호출 시 타입이 추론되는 경우가 많고
- 클래스 템플릿은 사용할 때 타입을 직접 적는 경우가 많다

입니다.

## 10. 클래스 템플릿이 특히 유용한 경우

자료구조는 구조는 같고 저장 원소 타입만 다른 경우가 많습니다.

예:

- `int` 스택
- `double` 스택
- `char` 스택

이때 각각 따로 클래스를 만들 필요 없이 `MyStack<T>` 하나로 해결할 수 있습니다.

즉, 클래스 템플릿은 자료구조의 일반화에 매우 잘 어울립니다.

## 11. 템플릿을 읽을 때 확인해야 할 질문

템플릿 코드를 볼 때는 "문법"만 보지 말고, 그 코드가 타입 `T`에게 무엇을 요구하는지도 같이 봐야 합니다.

예를 들어:

```cpp
T sum = 0;
sum += data[i];
```

이런 코드가 있으면 `T`는:

- `0`으로 초기화 가능해야 하고
- `+=` 연산이 가능해야 합니다

따라서 템플릿을 읽을 때는 항상 다음 질문을 해보면 좋습니다.

- 이 함수는 `T`를 어떻게 만들고 있나?
- `T`에 어떤 연산을 요구하나?
- 반환 타입과 인수 타입이 자연스럽게 맞는가?

## 12. STL이란

STL(Standard Template Library)은 C++ 표준 라이브러리 안의 템플릿 기반 도구 모음입니다.

대표 구성 요소:

- 컨테이너: `vector`, `map`
- 반복자: `iterator`
- 알고리즘: `sort`

STL의 장점은 다음과 같습니다.

- 이미 검증된 표준 도구를 쓸 수 있다
- 코드가 짧고 읽기 쉬워진다
- 컨테이너와 알고리즘을 공통 규칙으로 연결할 수 있다

chapter10의 뒷부분은 바로 이 표준 도구를 익히는 단계입니다.

## 13. `vector`

`vector`는 크기가 자동으로 늘어나는 배열입니다.

기본 형태:

```cpp
vector<int> v;
v.push_back(10);
v.push_back(20);
```

핵심 멤버:

- `push_back(x)` : 맨 뒤에 원소 추가
- `size()` : 현재 원소 개수
- `v[i]` : 인덱스로 접근
- `v.at(i)` : 범위를 검사하며 접근

배열과 비교하면:

- 배열은 크기가 고정된다
- `vector`는 원소가 추가되면 크기가 늘어난다

초급 단계에서는 `vector`를 "사용하기 편한 가변 길이 배열"이라고 이해해도 충분합니다.

## 14. `v[i]`와 `v.at(i)`의 차이

둘 다 원소에 접근할 수 있지만 성격이 다릅니다.

### `v[i]`

- 문법이 간단하다
- 빠르다
- 범위 검사 없음

### `v.at(i)`

- 범위를 벗어난 접근을 검사할 수 있다
- 잘못된 인덱스에 더 안전하다

초보자 입장에서는 다음처럼 이해하면 좋습니다.

- 값이 유효한 범위라고 확신하면 `[]`
- 실수 가능성을 줄이고 싶으면 `at()`

## 15. `vector<string>`도 가능하다

`vector`는 기본 타입만 담는 것이 아닙니다.

```cpp
vector<string> names;
```

처럼 `string`도 저장할 수 있고, 사용자 정의 객체도 저장할 수 있습니다.

이 점이 매우 중요합니다.  
`vector` 자체가 템플릿 클래스이기 때문에 원소 타입만 바꿔서 같은 구조를 재사용할 수 있습니다.

## 16. 문자열의 사전순 비교

`string`은 `<`, `>`, `==` 같은 비교 연산을 지원합니다.

예:

```cpp
if (a < b) ...
```

이 비교는 사전순(lexicographic order) 비교입니다.

즉:

- `"apple" < "banana"` 는 참
- 사전에서 앞에 오는지 뒤에 오는지를 비교하는 것과 비슷합니다

그래서 `vector<string>`에서 가장 앞이나 뒤에 오는 문자열을 찾는 문제를 쉽게 만들 수 있습니다.

## 17. 반복자(iterator)

반복자는 컨테이너의 원소를 가리키는 객체입니다.  
포인터와 비슷하게 생각해도 좋지만, STL 컨테이너를 순회하기 위한 표준 방식이라는 점이 더 중요합니다.

예:

```cpp
vector<int>::iterator it;
for(it = v.begin(); it != v.end(); ++it)
    cout << *it << ' ';
```

핵심 요소:

- `begin()` : 첫 번째 원소 위치
- `end()` : 마지막 원소의 다음 위치
- `*it` : 현재 위치의 원소
- `++it` : 다음 위치로 이동

## 18. 왜 `end()`가 중요한가

초보자가 가장 자주 헷갈리는 부분이 이것입니다.

`end()`는 마지막 원소를 가리키는 것이 아닙니다.  
정확히는 마지막 원소의 바로 다음 위치입니다.

따라서 다음은 하면 안 됩니다.

```cpp
*v.end()
```

올바른 패턴은 항상:

```cpp
for(it = v.begin(); it != v.end(); ++it)
```

처럼 `end()`와 비교만 하고, `end()`를 역참조하지 않는 것입니다.

## 19. `iterator`와 `const_iterator`

반복자는 쓰임이 두 가지로 나뉩니다.

### `iterator`

- 원소를 읽을 수 있다
- 원소를 수정할 수 있다

### `const_iterator`

- 원소를 읽을 수 있다
- 원소를 수정할 수 없다

예를 들어 출력만 하는 함수라면:

```cpp
void printVector(const vector<int>& v) {
    for(vector<int>::const_iterator it = v.begin(); it != v.end(); ++it)
        cout << *it << ' ';
}
```

처럼 `const_iterator`가 더 자연스럽습니다.

즉:

- 읽기 전용 순회면 `const_iterator`
- 값을 바꾸는 순회면 `iterator`

로 구분하는 습관이 좋습니다.

## 20. `map`

`map<K, V>`는 키(key)와 값(value)을 한 쌍으로 저장하는 자료구조입니다.

예:

```cpp
map<string, string> dic;
dic["apple"] = "사과";
```

의미:

- 키는 `"apple"`
- 값은 `"사과"`

입니다.

`map`은 사전, 상품명-재고, 학생번호-이름처럼  
"의미 있는 키로 값을 찾는 문제"에 아주 적합합니다.

## 21. `map`의 특징

핵심 특징:

- 키와 값의 쌍을 저장한다
- 키를 기준으로 데이터를 찾는다
- 키는 중복될 수 없다
- 키 기준으로 정렬된 상태를 유지한다

즉, `vector`가 "순서 중심"이라면 `map`은 "키 중심"이라고 볼 수 있습니다.

## 22. `map`의 기본 사용

먼저 `map`을 볼 때는 아래 그림을 머릿속에 두면 좋습니다.

- `map`의 원소 하나는 `(key, value)` 한 쌍이다
- key는 중복될 수 없다
- key를 기준으로 정렬된 상태를 유지한다
- 배열처럼 번호로 찾는 구조가 아니라 key로 찾는 구조다

즉, `map<string, string>`은  
"문자열 key에 문자열 value를 연결하는 표"라고 생각하면 이해가 쉽습니다.

삽입 방법:

```cpp
dic["apple"] = "사과";
dic.insert(make_pair("love", "사랑"));
```

### `pair`와 `make_pair`

위 코드에서 `insert(make_pair(...))`가 왜 나오는지도 이해해 두면 좋습니다.

- `pair`는 두 값을 함께 담는 자료형이다
- `make_pair(a, b)`는 두 값을 하나의 `pair` 객체로 만들어 주는 표준 함수다
- `map` 원소 하나가 `(key, value)` 쌍이므로 `insert()`에 넣을 때 `pair`가 필요하다

즉, `make_pair("love", "사랑")`는  
`("love", "사랑")` 한 쌍을 만들어 `insert()`에 넘기는 역할을 합니다.

조회 방법:

```cpp
cout << dic["apple"];
```

삭제 방법:

```cpp
dic.erase("apple");
```

개수 확인:

```cpp
cout << dic.size();
```

## 23. `find()`와 `operator[]`의 차이

이 부분은 실습과 시험에서 매우 자주 중요해집니다.

### `find(key)`

```cpp
if(dic.find("apple") == dic.end()) ...
```

- 키 존재 여부를 확인할 때 적합하다
- 키가 없으면 `end()`를 반환한다
- 조회 과정에서 원소를 멋대로 만들지 않는다

### `operator[]`

```cpp
dic["apple"] = "사과";
cout << dic["apple"];
```

- 삽입과 수정이 편하다
- 하지만 없는 키를 읽을 때 새 항목이 자동으로 생길 수 있다

그래서 실무 감각으로는 다음처럼 기억하면 좋습니다.

- 조회 중심이면 `find()`
- 삽입/수정 중심이면 `[]`

## 24. `map`의 값은 객체일 수도 있다

`map`의 값은 기본 타입일 수도 있고 클래스 객체일 수도 있습니다.

예:

```cpp
map<string, Item> stock;
```

이렇게 하면:

- 키는 상품명
- 값은 가격과 재고를 가진 객체

가 됩니다.

즉, `map`은 단순 번역 사전뿐 아니라 작은 데이터베이스처럼 사용할 수 있습니다.

## 25. `map` 반복자

`map`도 전체 데이터를 순회할 수 있습니다.

```cpp
for(map<string,int>::iterator it = m.begin(); it != m.end(); ++it) {
    cout << it->first << ":" << it->second << "\n";
}
```

여기서:

- `it->first` : 키
- `it->second` : 값

입니다.

이 문법은 `map` 원소 하나가 사실상 "키-값 쌍(pair)"이라는 점과 연결됩니다.

## 26. 알고리즘 `sort`

`sort`는 `<algorithm>` 헤더에 있는 대표적인 STL 알고리즘입니다.

기본 사용:

```cpp
sort(v.begin(), v.end());
```

의미:

- `v.begin()`부터
- `v.end()` 직전까지
- 오름차순으로 정렬한다

`sort`는 컨테이너의 멤버 함수가 아니라, 반복자 범위를 받는 전역 함수 템플릿입니다.

이 점이 매우 중요합니다.  
즉, STL은 "컨테이너"와 "알고리즘"을 반복자라는 공통 언어로 연결합니다.

## 27. `[begin, end)` 반열린 구간

STL에서 아주 자주 등장하는 표현이 있습니다.

```cpp
[begin, end)
```

이 뜻은:

- 시작 위치 `begin`은 포함
- 끝 위치 `end`는 제외

입니다.

따라서:

```cpp
sort(v.begin(), v.end());
```

는 벡터 전체를 정렬한다는 뜻입니다.

이 반열린 구간 개념은 `sort`뿐 아니라 iterator 기반 코드 전체를 이해하는 핵심입니다.

## 28. 기본 정렬 기준

`sort(v.begin(), v.end())`의 기본 정렬은 오름차순입니다.  
이때 원소 타입은 `<` 비교가 가능해야 합니다.

예:

- `int`는 가능
- `double`도 가능
- `string`도 가능
- 사용자 정의 클래스는 직접 비교 규칙을 제공해야 할 수 있음

즉, `sort`도 결국 템플릿이므로 원소 타입이 필요한 연산을 지원해야 합니다.

## 32. 시험이나 과제에서 바로 기억할 핵심 문장

- 템플릿은 타입만 다른 중복 코드를 줄이기 위한 도구다.
- 템플릿이 되려면 내부에서 쓰는 연산이 그 타입에서 가능해야 한다.
- 함수 템플릿은 동작을 일반화하고, 클래스 템플릿은 자료구조를 일반화한다.
- `vector`는 가변 크기 배열이다.
- `map`은 키와 값을 한 쌍으로 저장하는 자료구조다.
- `begin()`은 첫 원소, `end()`는 마지막 다음 위치다.
- 조회 중심이면 `find()`, 삽입/수정 중심이면 `[]`를 먼저 떠올리자.
- `sort(begin, end)`의 범위는 `[begin, end)`다.
